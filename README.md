# Narxoz Chess → Telegram

Личный трекер свободных мест на шахматах в [Sport Hub](https://sport.narxoz.kz/SectionDetail?id=s-chess). Проверяет весь опубликованный остаток семестра, сопоставляет реальные даты/время с расписанием пар и отправляет подходящие варианты в Telegram. Самостоятельной записи на занятие нет.

## Когда проверяет

- Каждые 30 минут круглосуточно: в `:07` и `:37`.
- За **8 часов 5 минут** и за **8 часов** до каждого подходящего еженедельного потока.
- Ручной запуск: Actions → Chess availability monitor → Run workflow.

Время пользователя — **Алматы, UTC+5**. Cron в workflow указан в UTC, включая перенос вторничной проверки на понедельник UTC. GitHub Actions может задержать или пропустить запуск при высокой нагрузке; точность до минуты не гарантируется. [Документация GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

При текущем расписании дополнительные проверки соответствуют:

| Поток | Проверки по Алматы |
|---|---|
| Пн 14:00 | Пн 05:55 и 06:00 |
| Вт 12:00 | Вт 03:55 и 04:00 |
| Вт 14:00 | Вт 05:55 и 06:00 |
| Вт 16:00 | Вт 07:55 и 08:00 |
| Ср 14:00 | Ср 05:55 и 06:00 |
| Чт 14:00 | Чт 05:55 и 06:00 |
| Пт 16:00 | Пт 07:55 и 08:00 |

Около 1 500–1 550 запусков в месяц. Реальные минуты зависят от длительности, повторов и других workflows аккаунта. Используется обычный Linux runner. Лимиты/расходы — в GitHub Billing; платёжные настройки этот проект не меняет. [Тарифы Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

## Правила уведомлений

- Учитываются отменённые бронирования, вместимость конкретного занятия, праздники/каникулы из Sport Hub, существующие записи пользователя и лимиты сайта.
- Уведомление приходит при первом обнаружении места, переходе «мест нет → есть», увеличении числа мест или изменении времени/места подходящего занятия. Неизменившийся слот не присылается повторно.
- Первый запуск сообщает текущие доступные варианты и статус запуска.
- После трёх подряд ошибок приходит предупреждение; после восстановления — сообщение об успешной проверке.
- В сообщении указаны дата, время, число мест, кабинет, срок отмены и кнопка открытия Sport Hub.
- Место не резервируется. Пока уведомление идёт, другой студент может занять его.
- Если место заняли и снова освободили полностью между двумя проверками, такой промежуточный переход обнаружить нельзя.

Расписание из скриншота находится в `schedule.json`, действует до **26.12.2026**. Добавочные занятые интервалы можно внести в `extra_busy`. Касание границ не считается пересечением; `buffer_minutes` задаёт запас на переход. Конец субботней физкультуры на скрине не виден: после 19:30 суббота консервативно закрыта до полуночи, что не затрагивает текущие шахматные потоки.

При изменении пар нужно обновить `schedule.json`; при изменении времени шахмат — также дополнительные cron в `.github/workflows/monitor.yml`. Обычные проверки всегда анализируют реальные занятия API. После срока действия расписания бот сообщает, что расписание нужно обновить, и workflow автоматически отключается, чтобы не расходовать минуты. После обновления включить его через Enable workflow.

## Секреты и состояние

Приватный репозиторий. В GitHub Actions Secrets нужны:

| Secret | Назначение |
|---|---|
| `SPORT_USERNAME` | Номер студента или email |
| `SPORT_PASSWORD` | Пароль Sport Hub |
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `TELEGRAM_CHAT_ID` | ID подтверждённого личного чата |

`GITHUB_TOKEN` создаётся Actions автоматически. Пароли, токены, фото, email и чужие записи не сохраняются в репозитории, состоянии или логах. Исходный ответ Sport Hub обрабатывается только в памяти.

Ветка `monitor-state` содержит `state.json` с историей обнаруженных мест и последним успешным запуском. История переживает обновления кода и очистку кеша. Workflow использует одну concurrency group, запись состояния проверяет SHA, поэтому параллельные обновления не перетирают друг друга. Отсутствие или повреждение истории вызывает ошибку вместо массовой повторной рассылки.

Доставка имеет семантику повторной попытки: редкий сбой между принятием сообщения Telegram и сохранением состояния может вызвать дубликат. Потеря недоставленного уведомления предотвращается сохранением отметки только после успешного ответа Telegram.

## Локальная проверка

Python 3.11+; сторонние библиотеки не требуются. Передать Sport Hub credentials через переменные окружения.

```sh
python -m unittest discover -s tests -v
python tracker.py --dry-run
```

`--dry-run` проверяет реальный API, не отправляет сообщения и не изменяет историю. Обычный запуск — `python tracker.py` в Actions. Для локального запуска с рассылкой нужен явно инициализированный файл состояния и `--state-file PATH`.

Для остановки: Actions → Chess availability monitor → Disable workflow. Для продолжения — Enable workflow.
